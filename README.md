# AniForge · MMD LoRA Studio

Blender MMD 三渲二与角色训练图插件。正式输出 **39 张互补的照片：12 肖像 + 9 半身 + 9 全身 + 9 穿着服装的细节**，联合覆盖脸部、表情、站/坐姿、侧背轮廓和服饰。每个拍摄位置只输出一张，不为每个 Pose 扩展三视图。开发用三视图仍用于快速排查；正式肖像四视图属于 12 张肖像的一部分。

项目仓库：[haotemans/AniForge](https://github.com/haotemans/AniForge)。仓库提供源码与测试工具，本地模型、贴图、渲染图和第三方插件安装包不包含在源码中。

已使用本机 **Blender 5.2.2 LTS** 进行集成测试。插件声明最低 4.2，但其他版本尚未验证。

## 安装与使用

1. 下载或克隆源码后运行 `python tools/build_zip.py`，生成 `dist/mmd_lora_studio-0.8.1.zip`。Blender → 编辑 → 偏好设置 → 插件 → 右上角菜单 → 从磁盘安装，选择该 ZIP，启用 AniForge - MMD LoRA Studio。也可将 `mmd_lora_studio` 文件夹复制到 Blender 的 scripts/addons 目录。
2. 使用适配你 Blender 版本的 MMD Tools 导入 PMX / PMD。已有 `.blend` 角色可直接使用。本插件不包含 PMX/PMD 解析器、游戏资产和贴图。
3. 在 3D 视图按 N，打开 **MMD LoRA** 面板，指定角色骨架。通过父子关系或骨架修改器识别相关网格。
4. 贴图路径丢失时，选择贴图目录，点击“重连丢失贴图”。仅匹配唯一的同名文件；同名冲突不会任意选择。
5. 尚未绑定底色贴图时，可点击“按材质名匹配底色贴图”。支持 `材质名.png`、`材质名_BaseColor.png`、`材质名_Albedo.png`、`材质名_Diffuse.png`、`材质名_Color.png` 及其他常见图片扩展名。支持 MMD 材质中日英名称，多个候选时跳过。复杂 MMD 节点保留，匹配图作为后续三渲二转换的底色来源。
6. 选择游戏风格，点击“应用三渲二材质”。该操作支持撤销，原材质数据设置为保留用户，保存并重新打开工程后仍可切换风格。明确读取 MMD Tools 的 `mmd_base_tex`，不将 Toon / Sphere 当底色。一般材质使用底色、透明度及两段光照；MMD 自带的半透明阴影、高光或隐藏层保留原节点，避免破坏其混合逻辑。
7. 逐项预览表情和姿势。对不适合当前模型的预设，手动调好后，点击“保存当前为预设”，覆盖面板当前选中的名称。自定义预设随 `.blend` 保存。
8. 输入英文触发词，例如 `my_character`，按实际角色填写附加标签。默认输出目录为 `.blend` 文件旁的 `lora_dataset`；未保存工程时建议指定绝对路径。
9. 默认正面为世界 -Y，模型朝向其他方向时修改“角色正面角度”。在“输出”页查看拍摄清单，可先无出图预览或只渲染选定的一张，再点击“生成角色数据集：共 39 张 + 标签”。

## 12 张方形白底肖像（本 PR）

- 肖像 **12 张，1:1 方形，纯白背景 RGB(255,255,255) / #FFFFFF**；整个数据集现在共 **39 张**。半身、全身、服装细节仍各 9 张，后续单独讨论半身 10 镜头方案。
- 标准头部四视图（1–4）：正面 0°、左侧 90°、右侧 -90°、背面 180°；中性表情、头部中正，相机绕角色移动，避免仰拍。四张均是正式数据集的一部分。
- 八张特色肖像（5–12）：比耶 Wink、惊喜、甜美笑容、害羞、调皮点脸、傲娇、元气开心、温柔回眸。表情和手势是可调整的起始模板，MMD 形态键缺失时不会编造已成功映射的标签。
- 肖像组独立强制方形，其他组保留原 3:4 透视构图。输出继续按角色、分组编号配对 PNG/TXT，并在 manifest 中记录每张镜头。
- 老版本镜头替换 JSON 支持从 schema_version=1 升级到 2，历史肖像镜头映射到对应的表情槽位，避免覆盖新增的四视图；原有非肖像组位置不变。
- 当前未对真实角色模型执行可视化渲染验收。请检查长发遮挡、左右侧定义、手指是否完整入镜及眼部形态键兼容性。

拍摄表：[39 张拍摄编排](docs/shot_plan.md)。

## 0.8.1 移除衣服物理

删除衣服/头发的自动模拟、代理求解器、后台稳定进程、物理参数页和物理补入操作。渲染直接使用角色当前骨骼蒙皮变形，不再等待稳定帧或创建物理烘焙网格。旧工程即使保存了开启物理的参数，也不会重新启用这一流程。

渲染期间临时停用场景刚体世界、当前角色的 MMD 刚体追踪约束及 Cloth / Soft Body 修改器，结束或出错后还原原设置。不会删除原模型中的刚体、关节、权重、材质或骨骼。衣服跟随现有绑定；坐姿与手势的穿模需要逐个动作调整，不自动通过物理修复。17 个内置姿势、8 个表情、本地 VPD 库、坐凳和 36 张拍摄编排保留。

## 坐姿与角色信息覆盖

- 内置 **17 种姿势、8 种表情**。端坐与侧坐按实际腿长弯曲髋/膝、降低身体、放置简洁坐凳；临时切换腿部 IK，批次结束恢复原控制。默认 36 张中有 2 张全身坐姿和 1 张半身坐姿，其余位置覆盖站立、手势、侧背轮廓与表情。屈膝地坐尚未列入当前预设。
- 自动坐凳是构图支撑物。衣服仅使用骨骼蒙皮，需要检查裙摆、袖子和披风在当前动作下的形状。
- 服装九张现覆盖领口颈饰、胸肩、左右袖子手套、腰饰、下装、下摆腿部、背部、鞋靴足饰。清单附带**计划覆盖信息**；完整批次总数保持 36，三视图检查不属于正式编排。真实遮挡和标签仍按最终图像验收。


## 0.6.0 二次元姿势与 36 张联动编排

目标输出固定为 **9 肖像 + 9 半身 + 9 全身 + 9 穿着服装的细节照**。每张都有单独编排的姿势、表情、头部角度、手型、拍摄角度和取景目标；没有表情 × 姿势 × 镜头的额外组合。完整清单见 [36 张拍摄编排](docs/shot_plan.md)。

- 内置姿势增加到 **15 种**：自然站姿、单手叉腰、招手、张开双臂、双手身前、单手展示、脸侧剪刀手、托腮思考、害羞收手、元气举手、猫爪手势、俏皮敬礼、背手前倾、侧身立绘、服装展示。基础表情仍为 **8 种**。
- 二次元姿势加入轻微躯干扭转、肩胯反向倾斜与歪头。脸侧手势按当前骨架肩宽/头部位置求手部目标，再计算两段手臂方向，避免仅套固定关节角。手型“跟随姿势”可左右不同，剪刀手带两指展开。腿部没有新增坐、蹲、迈步解算，复杂脚部 IK 和服装碰撞仍需检查。
- 肖像以脸部定位，指定脸侧手势会把手部范围纳入画面；半身按动作保留指定手势；全身按最终姿势的包围盒留白，包含侧面与背面。背面图片以服装/轮廓为目标，不承担正脸表情信息。
- 服装组固定 9 个区域：领口颈饰、胸前肩饰、左袖手套、右袖手套、腰带腰饰、下装侧饰、下摆腿部、背部上装、背面腰饰。采用手臂让开的展示姿势。这些是按骨架/身高定位的区域，无法保证每个角色都有对应服饰，也不会自动拨开发丝、披风或解决遮挡。
- 联动编排默认 3:4 竖幅、透视、肖像 85 mm / 其他 70 mm，并使用各张指定的头部、手型和强度；只读取这些临时参数，不覆盖面板里的个人设置。角色正面、输出分辨率与路径仍由用户设置。“当前姿势 / 表情 / 镜头参数”模式沿用用户的控制，保留四组各九个拍摄目标。

使用“输出”页，先选择 **预览构图 + 组内镜头 1–9**，点击“预览编排镜头（不出图）”检查对应效果。“查看 36 张拍摄清单”写入 Blender 文本编辑器。可渲染当前编排的一张，随后选择完整 36 张输出。

参考了 [CLIP STUDIO 的动作线、平衡与姿势教程](https://www.clipstudio.net/how-to-draw/archives/156164) 和 [肩胯反向倾斜及镜头构图教程](https://tips.clip-studio.com/en-us/articles/6073)。内置姿势是程序化设计，没有打包第三方 VPD。网上的现成姿势仍可通过 VPD 导入，例如作者发布的 [Simple pose pack for model references](https://www.deviantart.com/whyareyouthatsad/art/DL-Simple-pose-pack-for-model-references-883920854)；实际下载/使用依作者页面和包内说明。

## 姿势、表情与镜头基础功能（0.5.0 起）

面板分为“材质 / 姿势 / 镜头 / 输出”四页。材质规则沿用 0.4.0，日常测试依然以三视图为限。

**姿势与表情**

- 姿势支持 0–1 强度。重复应用从受管理骨骼的参考方向求解，不重复叠加旋转。内置模板控制躯干、头部和上肢；从复杂全身姿势切回模板时可先“恢复静置姿势”。
- 头部可独立调整俯仰、转向与歪头。默认手型跟随姿势，也可保留当前或指定轻微放松、握拳、食指指向、剪刀手。手型使用局部关节角度，骨轴、IK、服装因模型而异，必须逐个动作检查。
- 表情支持 0–1 强度。微笑优先使用嘴角，开心混合嘴角/眼部/小幅张嘴，闭眼和眨单眼独立；名称匹配兼容常见中日英名及全角数字。基础表情的实际可用通道仍以模型形态键为准。
- 填写“新预设名称”，手动调整后点击“保存当前”，可新增命名姿势/表情；留空会覆盖当前选中名称。保存时将当前效果烘入预设并恢复强度为 1，避免二次缩放。
- 默认只捕获识别出的脸部键，保留体型等其他形态键；特殊表情可勾选“保存全部形态键”。已有自定义表情里的键也会参与该表情库的清零管理。
- “检查骨骼与表情映射”生成 Blender 文本 `AniForge Mapping Report`，显示命中、缺失与活动约束。JSON 中的 `bone_map` 可覆盖逻辑骨骼名，例如 `{"left_arm": "角色实际左上臂骨名"}`。
- 可导入 VPD，使用已启用的 MMD Tools 解析格式并转换坐标，由 AniForge 直接保存静态局部矩阵，不创建或绑定 Action。VPD 含表情时一并保存。默认缩放 0.08；复杂约束和不同骨轴仍须在当前模型上检查。

**镜头与工作流**

1. 在“姿势”页选择姿势、表情与强度，点击应用，或保存手动调整的结果。
2. 在“镜头”页选择构图。肖像可选按脸部网格定位的头肩范围或脸部特写；半身构图不会为了容纳长发而自动扩成全身。全身仍按完整包围盒留白。
3. 选择正交或透视；透视支持 20–200 mm 焦距。另可调环绕、俯仰、画面倾斜、缩放、水平/垂直移轴及按身高比例的对焦偏移。画幅支持 1:1、3:4、4:3，“分辨率”表示长边像素。
4. 点击“应用姿势表情并生成预览相机”，更新专用相机并进入相机视角，**不会渲染图片**。每次生成预览或出图都会按面板参数重新构图；直接拖动预览相机不会自动同步面板参数。
5. 镜头参数可命名保存。预设保存相对构图参数，应用到当前模型时重新计算位置，不固定上一模型的绝对坐标。
6. 在“输出”页检查编排清单，需要画面检查时渲染选定的一张，再生成完整 36 张。开发用三视图收在“显示开发用三视图测试”中；脚本的三视图默认值只是开发预算，不代表正式数据集的组织方式。

三类预设、腿部控制选项和镜头替换可合并导入/导出同一个 JSON（支持旧版表情/姿势存储迁移，文件上限 8 MiB）。自定义姿势保存实际骨名与局部矩阵，并不承诺异构骨架的自动重定向；换模型时优先重新导入 VPD 或检查骨名/骨轴。切换回其他姿势时恢复自定义动作涉及的控制，批次结束恢复原姿势、形态键、相机和渲染参数；预览按钮造成的编辑则保留在当前场景中，可撤销。

## 0.4.0 眼部、颈圈与小批量测试

- 锁暝的虹膜、眼白和眼部覆盖层使用独立颜色通路；鸣潮眼部使用 EEVEE 的 BLENDED 透明方式，避免透明层透出错误的暗色。其他游戏保持 DITHERED，避免打乱虹膜与眼白排序。保留原眼睛贴图和瞳孔图案，不改画原贴图。
- 菲欧妮的皮肤覆盖层与颈圈附近贴花使用独立颜色/Alpha 通路，避免透明黑色遮住白色领口细节。
- 新增 `EYE`、`DECAL` 材质角色，支持在原材质的 `mmd_lora_role` 自定义属性中手动指定。
- 普通测试默认不渲染；需要真实画面验证时，每个受影响角色只用正/侧/背三张。历史完整 A/B 对比需要显式 `--full-comparison`，完整数据集需要显式 `--phase full` 或面板按钮。
- `bpy.ops.ml.render_dataset()` 现在默认三视图；完整导出需显式指定 `test_only=False`。

此处的透明方式选择参考 [Blender 5.2 EEVEE 支持节点与限制](https://docs.blender.org/manual/en/5.2/render/eevee/limitations/nodes_support.html)，最终以本机模型的三视图验证为准。

## 0.3.0 头发与脸部优化

“头发 / 脸部优化”默认开启；参数修改后重新点击“应用三渲二材质”。关闭后可恢复 0.2.0 的通用着色规则作对照。

- 自动区分头发主体、高光覆盖层、脸部和脸部阴影层；按常见材质名匹配，不把服装饰品当成头发。可在原材质自定义属性 `mmd_lora_role` 中手动指定 `HAIR`、`HAIR_HIGHLIGHT`、`FACE`、`FACE_SHADOW` 或 `GENERIC`。
- 对识别出的高光覆盖层，按“头发高光层强度”缩放不透明度，默认 0.22。原始底色、UV、几何与发色不改写，保留发丝底色与纹理细节。
- 鸣潮锁暝的高光 PNG 为带 Alpha 的高位深图片，MMD 导入后错误地使用 `alpha_mode=NONE`。为这类已识别的高光层复制 Blender 图像数据块并恢复 STRAIGHT Alpha；不修改原图片文件或原图像数据块。
- 原始贴图中菲欧妮的发色是浅金色；旧转换将覆盖层的黑色区域盖在底色上。降低覆盖层并正确处理透明度后，恢复原贴图的浅金发色。
- 脸部使用平滑法线与低对比明暗，避开真实发丝投影造成的硬黑斑；“脸部柔和补光”默认 0.92。额外的发影/目影层保留原节点并将强度缩放至原值的 0.3。
- 这是没有专用脸部 SDF 贴图时的风格化近似，不是游戏原版 SDF 实现。脸部法线相对于场景中的固定补光方向计算；尚未绑定专用动态主光。

`tools/run_material_profiles.py --full-comparison` 保留历史多图对比功能；日常验证使用下面的三视图命令。

## 输出规则

| 分组 | 数量 | 默认构图 |
| --- | ---: | --- |
| portrait | 9 | 按脸部定位的头肩/特写，部分镜头保留脸侧手势 |
| half_body | 9 | 上半身 |
| full_body | 9 | 全身，按姿势后的包围盒留白 |
| outfit_detail | 9 | 穿在角色身上的九个服装区域，含袖子与背面 |

完整数据集使用各组独立的九个镜头，全身和服装包含侧面/背面；共 36 张。输出使用独立时间戳目录，保留历史批次。

```text
lora_dataset/my_character_时间戳/
  manifest.json
  portrait/*.png + *.txt
  half_body/*.png + *.txt
  full_body/*.png + *.txt
  outfit_detail/*.png + *.txt
```

清单记录计划、实际映射的形态键/骨骼、图片路径、标签和完成状态。失败或取消时保留已有图片。缺失表情映射会标记为 neutral，近似的内置骨骼姿势不会自动写成经过确认的姿势标签。自动标签只是初稿，训练前应按实际画面校正。

## 六款游戏风格的范围

包含崩坏：星穹铁道、绝区零、原神、鸣潮、明日方舟：终末地、异环。当前预设调整色阶阈值和阴影色强度，属于**通用风格近似**，不等于这六款游戏原版着色器。

尚未实现各游戏的脸部 SDF、LightMap/通道遮罩解析、原版头发高光、描边、特殊眼睛和游戏专用材质分类。不会生成缺失贴图，也不会自动下载游戏模型。对精确还原，需要按实际资产补充对应节点与贴图通道。

## 表情和姿势的范围

- 内置八种基础表情与十七个姿势，按常见 MMD/英文命名映射；MMD Tools 的“组变形”不在这一版解析范围内。
- 目标方向解算兼容不同 A/T 初始姿势和骨骼滚转角；复杂 IK、约束、袖子和披风仍须预览或手动覆盖。衣服只使用原有骨骼蒙皮。
- 当前按 Z 轴朝上、单一角色设计。肖像/半身有意裁切远离主体的长发、大头饰和道具；需要完整展示时选全身。半身和服装区域优先按骨架定位，随坐姿调整；不识别服装语义或自动脱离角色。
- 骨架有活动 Action 时拒绝批量渲染。使用角色副本并解除动画；NLA、驱动和形态键动画也可能覆盖预设，应先处理。

## 渲染与恢复

使用 EEVEE，因为 Shader to RGB 仅支持 EEVEE。按所选投影生成临时相机、灯光与纯色背景；坐姿还会生成简洁坐凳。渲染时隐藏其他网格和灯光；角色自身的隐藏状态和集合可见性仍需要预先检查。

批次完成、错误或取消后恢复原相机、灯光/其他网格的渲染可见性、骨骼姿势、形态键、世界背景及批次修改的渲染设置。手动应用的材质是持久编辑，不会在批次结束后撤销。渲染期间请等待完成，Esc 会在当前单张结束后停止，单张渲染期间界面可能无响应。

PNG 默认方形长边 1024，长边范围 256–4096；竖幅/横幅按 3:4/4:3 输出。36 张是起始素材，是否足以训练取决于角色复杂度与图片质量；应去掉穿模、重复、错误表情和错误标签。
