# API 图片打标

最终标签为插件本地拼接：`@3d, 角色名, API图片详细描述`。角色名由用户填写，不让模型猜测，也不作为文字字段发往API。

角色名中的下划线默认转为空格并合并重复空白，例如`phoenix_reffaella`最终写入`@3d, phoenix reffaella, ...`。仅规范化本地角色名前缀，描述正文与文件命名不变；缓存描述继续复用，补标会在本地重写新前缀。

每张图片对应一个同目录、同文件名的UTF-8 TXT，例如：

```text
mingyin_portrait_01.png
mingyin_portrait_01.txt
```

TXT内容示例仅说明格式，实际描述来自配置的视觉模型：

```text
@3d, 明音, A front-facing 3D anime character with long blonde hair, pink eyes, a dark headband, blue musical-note hair clips, a white collared shirt and a black choker. ...
```

## 配置

在“渲染与输出”填写角色名，开启“渲染后API打标”，展开“API图片打标”：

- **Base URL**、**API Key**、**视觉模型**由用户填写。接口需兼容Chat Completions图像输入和JSON对象输出。
- Base URL支持HTTP和HTTPS，例如`https://your-provider.example/v1`或`http://your-provider.example:3000/v1`；也可填写完整的`/chat/completions`地址。允许HTTP地址携带用户填写的Key；不自动跟随重定向，不把Key转发到其他地址。没有内置付费账户或默认供应商。
- Key以密码框显示，仅保存在本机Blender偏好设置，不写入角色工程、清单、缓存或源码。“保存API设置”不会请求模型。
- 默认使用用户提供的视觉依据优先的英文系统提示词；细节充分时约140–240词，稀疏画面可更短。逐张独立观察主体、动作互动、服装饰物、环境及画面表现，使用连贯段落；不补写遮挡部位、故事、性格、关系、确切年龄、图外事件或身份。可按偏好设置覆盖为中文，仍遵循相同画面核对规则。手动“基础附加标签”字段及旧值已移除，不向接口发送人工附加描述。

接口图像输入形式参考[官方多图与Base64输入说明](https://developers.openai.com/api/docs/guides/images-vision)。本插件仅依赖兼容的HTTP协议，不安装SDK。

## 请求与响应

原始4K图片保持不变。插件仅在内存中按原比例缩小，最长边不超过1024，不拉伸、不补方图，不放大小图，再压缩为PNG/Base64；不生成额外缩略图文件。例如4096×2048变为1024×512，2048×4096变为512×1024。

固定batch=1，每个请求只发送一张图片，顺序处理；16张待打标图片正常分成16次请求，成功缓存继续复用，不因批量大小或重试策略改变而重新请求成功结果。JSON请求包含`model`、`messages`、`response_format: {"type":"json_object"}`和`max_tokens: 4096`，图片位于用户消息的`image_url`数据URI中，附带不含角色名和文件路径的ID，响应的`images`数组只返回该图片的一项。

模型返回的描述内容须为：

```json
{
  "images": [
    {"id": "image_001", "caption": "Only a detailed description of this image."}
  ]
}
```

兼容返回`choices[0].message.content`内的JSON，或直接返回以上对象；解析器仍兼容旧版`description`键，新提示词统一要求`caption`。响应顺序可以改变，插件按ID匹配原图；缺图、重复ID、错误ID、空描述或截断结果会使本批失败，不把描述错配到其他图片。

## 自动打标与补打标

渲染前检查配置，渲染结束后再请求描述。API模式下不会用简单模板冒充详细描述：成功后才生成TXT，失败时保留PNG，在界面和清单中标明失败。

HTTP 408、429、5xx，连接失败／超时，以及无效JSON、缺项、错误ID或空描述会自动重试当前图片，最多3次请求（首次加2次重试，间隔1秒、2秒）。等待期间界面仍可操作，停止打标会取消尚未开始的重试。HTTP 400、401、403等配置／认证错误、明确的输出截断以及本地图片或文件写入错误不会自动重复请求。已成功的图片不参与重试；已缓存但TXT保存失败的描述可在补标时直接恢复，无需再次请求API。

界面明确区分“图片渲染完成”和“API打标完成”；未齐全时显示成功／总数、失败数量及具体失败文件。任务结束时检查实际同名TXT及其内容，缺失文件不会记作完成。清单的`status`记录渲染状态，`dataset_status`记录数据集状态：只有全部TXT核对通过才为`READY`，失败为`CAPTION_FAILED`，主动停止为`CAPTION_STOPPED`。`captioning.attempts`记录本轮各图片的请求次数，`errors`保留最终失败文件及原因；不保存Key或接口原始响应。

“另选目录（可选）”留空时，点击“打标已有图片／重试失败项”默认使用上方当前“输出到”目录，不重新渲染。该目录直接包含图片或旧版清单时直接处理；若是渲染总目录，选择当前角色最近一次有图片的子目录，跳过空的中断记录，不递归混扫其他角色。改了输出位置后按新位置查找，不拿别处的旧输出补标。同一角色独用的输出总目录支持角色名前缀改名后继续使用该目录中的最近记录；多角色有歧义时需另选具体图片目录。显式另选的目录优先于默认输出。

图片与同名TXT平铺在同一个角色目录。有效描述缓存与清单保存在角色目录外、同级`.aniforge/`中的专属子目录，图片目录不混入JSON或临时文件；旧版目录内的缓存和清单仍可读取。缓存按原图内容、接口/模型、语言、提示版本和该图镜头提示核对。改角色名只在本地更新TXT前缀；原图与接口配置未变时复用成功描述，不重复请求API。失败项可单独重试。Key不参与缓存。本次系统提示词版本升级为3，已有描述会在下一次主动打标时按新规则重新请求。

每张图的文本JSON与图片ID一起携带`render_context`：取景范围（肖像、半身、全身、腿脚细节）、方向（正/侧/背/斜侧）和清单中实际镜头角度。例如下半身背面会给出`lower-body detail`和`rear view, from behind`，帮助API关注可见腿部、袜面与鞋子。提示与实际图片冲突时以图片为准，不据此补写看不到的五官或肢体。每张图的提示独立绑定其ID，不在批次间串用。

提示优先取自渲染清单；没有清单时，只有可识别的取景类型可从本插件文件名结构恢复，方向不根据数字序号推断（历史三视图03与正式四视图03含义不同）。白名单只传递镜头信息，不传角色名、文件名、目录或任意清单文本。只修改一张图的镜头提示时，该图缓存单独失效。

交互模式使用后台线程请求网络，界面显示完成数和失败数。“当前批次后停止打标”会保存当前批次结果，然后停止后续请求。关闭插件或打开其他工程时停止跟踪旧任务。普通回归测试只使用本机模拟HTTP服务，不访问用户接口、不渲染图片。
