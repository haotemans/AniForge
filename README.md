# AniForge · MMD LoRA Studio

Blender MMD 三渲二与批量渲染插件。默认先用正面、侧面、背面三视图测试材质；需要制作数据集时，再手动选择完整 36 张输出。包含六款游戏的通用风格近似、表情和姿势预设、贴图重连与材质优化。

项目仓库：[haotemans/AniForge](https://github.com/haotemans/AniForge)。仓库提供源码与测试工具，本地模型、贴图、渲染图和第三方插件安装包不包含在源码中。

已使用本机 **Blender 5.2.2 LTS** 进行集成测试。插件声明最低 4.2，但其他版本尚未验证。

## 安装与使用

1. 下载或克隆源码后运行 `python tools/build_zip.py`，生成 `dist/mmd_lora_studio-0.4.0.zip`。Blender → 编辑 → 偏好设置 → 插件 → 右上角菜单 → 从磁盘安装，选择该 ZIP，启用 AniForge - MMD LoRA Studio。也可将 `mmd_lora_studio` 文件夹复制到 Blender 的 scripts/addons 目录。
2. 使用适配你 Blender 版本的 MMD Tools 导入 PMX / PMD。已有 `.blend` 角色可直接使用。本插件不包含 PMX/PMD 解析器、游戏资产和贴图。
3. 在 3D 视图按 N，打开 **MMD LoRA** 面板，指定角色骨架。通过父子关系或骨架修改器识别相关网格。
4. 贴图路径丢失时，选择贴图目录，点击“重连丢失贴图”。仅匹配唯一的同名文件；同名冲突不会任意选择。
5. 尚未绑定底色贴图时，可点击“按材质名匹配底色贴图”。支持 `材质名.png`、`材质名_BaseColor.png`、`材质名_Albedo.png`、`材质名_Diffuse.png`、`材质名_Color.png` 及其他常见图片扩展名。支持 MMD 材质中日英名称，多个候选时跳过。复杂 MMD 节点保留，匹配图作为后续三渲二转换的底色来源。
6. 选择游戏风格，点击“应用三渲二材质”。该操作支持撤销，原材质数据设置为保留用户，保存并重新打开工程后仍可切换风格。明确读取 MMD Tools 的 `mmd_base_tex`，不将 Toon / Sphere 当底色。一般材质使用底色、透明度及两段光照；MMD 自带的半透明阴影、高光或隐藏层保留原节点，避免破坏其混合逻辑。
7. 逐项预览表情和姿势。对不适合当前模型的预设，手动调好后，点击“保存当前为预设”，覆盖面板当前选中的名称。自定义预设随 `.blend` 保存。
8. 输入英文触发词，例如 `my_character`，按实际角色填写附加标签。默认输出目录为 `.blend` 文件旁的 `lora_dataset`；未保存工程时建议指定绝对路径。
9. 默认正面为世界 -Y，模型朝向其他方向时修改“角色正面角度”。选择构图后点击“三视图测试：正 / 侧 / 背”，仅渲染 0°、90°、180° 各一张，使用中性表情和放松姿势。默认先检查这三张；只有明确需要完整数据集时，才点击“完整数据集：36 张 + 标签”。

## 0.4.0 眼部、颈圈与小批量测试

- 锁暝的虹膜、眼白和眼部覆盖层使用独立颜色通路；鸣潮眼部使用 EEVEE 的 BLENDED 透明方式，避免透明层透出错误的暗色。其他游戏保持 DITHERED，避免打乱虹膜与眼白排序。保留原眼睛贴图和瞳孔图案，不改画原贴图。
- 菲欧妮的皮肤覆盖层与颈圈附近贴花使用独立颜色/Alpha 通路，避免透明黑色遮住白色领口细节。
- 新增 `EYE`、`DECAL` 材质角色，支持在原材质的 `mmd_lora_role` 自定义属性中手动指定。
- 普通测试默认不渲染；需要真实画面验证时，每个受影响角色只用正/侧/背三张。历史完整 A/B 对比需要显式 `--full-comparison`，完整数据集需要显式 `--phase full` 或面板按钮。
- `bpy.ops.ml.render_dataset()` 现在默认三视图；完整导出需显式指定 `test_only=False`。

此处的透明方式选择参考 [Blender 5.2 EEVEE 支持节点与限制](https://docs.blender.org/manual/en/5.2/render/eevee/limitations/nodes_support.html)，最终以本机模型的三视图验证为准。

## 0.3.0 头发与脸部优化

“头发 / 脸部优化”默认开启；参数修改后重新点击“应用三渲二材质”。关闭后可恢复 0.2.0 的通用着色规则作对照。

- 自动区分头发主体、高光覆盖层、脸部和脸部阴影层；按常见材质名匹配，不把服装饰品当成头发。可在原材质自定义属性 `mmd_lora_role` 中手动指定 `HAIR`、`HAIR_HIGHLIGHT`、`FACE`、`FACE_SHADOW` 或 `GENERIC`。
- 对识别出的高光覆盖层，按“头发高光层强度”缩放不透明度，默认 0.22。原始底色、UV、几何与发色不改写，保留发丝底色与纹理细节。
- 鸣潮锁暝的高光 PNG 为带 Alpha 的高位深图片，MMD 导入后错误地使用 `alpha_mode=NONE`。为这类已识别的高光层复制 Blender 图像数据块并恢复 STRAIGHT Alpha；不修改原图片文件或原图像数据块。
- 原始贴图中菲欧妮的发色是浅金色；旧转换将覆盖层的黑色区域盖在底色上。降低覆盖层并正确处理透明度后，恢复原贴图的浅金发色。
- 脸部使用平滑法线与低对比明暗，避开真实发丝投影造成的硬黑斑；“脸部柔和补光”默认 0.92。额外的发影/目影层保留原节点并将强度缩放至原值的 0.3。
- 这是没有专用脸部 SDF 贴图时的风格化近似，不是游戏原版 SDF 实现。脸部法线相对于场景中的固定补光方向计算；尚未绑定专用动态主光。

`tools/run_material_profiles.py --full-comparison` 保留历史多图对比功能；日常验证使用下面的三视图命令。

## 输出规则

| 分组 | 数量 | 默认构图 |
| --- | ---: | --- |
| portrait | 9 | 头部与肩部，按角色高度估算 |
| half_body | 9 | 上半身 |
| full_body | 9 | 全身，按姿势后的包围盒留白 |
| outfit_detail | 9 | 穿在角色身上的躯干至大腿服装细节 |

每组使用 -55° 到 +55° 的九个角度，并搭配预设表情、姿势；共 36 张，不是每个角度再组合全部表情和姿势。输出使用独立时间戳目录，保留历史批次。

```text
lora_dataset/my_character_时间戳/
  manifest.json
  portrait/*.png + *.txt
  half_body/*.png + *.txt
  full_body/*.png + *.txt
  outfit_detail/*.png + *.txt
```

清单记录计划、实际映射的形态键/骨骼、图片路径、标签和完成状态。失败或取消时保留已有图片。缺失表情映射会标记为 neutral，近似的内置骨骼姿势不会自动写成经过确认的姿势标签。自动标签只是初稿，训练前应按实际画面校正。

## 六款游戏风格的范围

包含崩坏：星穹铁道、绝区零、原神、鸣潮、明日方舟：终末地、异环。当前预设调整色阶阈值和阴影色强度，属于**通用风格近似**，不等于这六款游戏原版着色器。

尚未实现各游戏的脸部 SDF、LightMap/通道遮罩解析、头发高光、描边、特殊眼睛、物理和游戏专用材质分类。不会生成缺失贴图，也不会自动下载游戏模型。对精确还原，需要按实际资产补充对应节点与贴图通道。

## 表情和姿势的范围

- 内置中性、微笑、开心、闭眼、眨单眼、生气、悲伤、惊讶；按常见日文及英文形态键名称映射。MMD Tools 的“组变形”不在这一版解析范围内。
- 内置放松、叉腰、招手、张开双臂四个起始姿势；按常见 MMD 和部分英文骨骼名映射。0.2.0 使用目标手臂方向解算，兼容不同 A/T 初始姿势和骨骼滚转角；复杂 IK、约束、袖子和披风仍须预览或手动覆盖，未自动模拟布料或刚体。
- 内置表情仅归零受管理的表情键；不主动清除其他体型形态键。保存自定义表情会捕获当前网格的全部非 Basis 键。
- 当前按 Z 轴直立、单一角色设计。超长头饰、大型道具、极端姿势可能影响自动构图；服装细节目前为统一躯干裁切，不识别服装语义或自动脱离角色。
- 骨架有活动 Action 时拒绝批量渲染。使用角色副本并解除动画；NLA、驱动和形态键动画也可能覆盖预设，应先处理。不会自动烘焙动画或物理。

## 渲染与恢复

使用 EEVEE，因为 Shader to RGB 仅支持 EEVEE。生成临时正交相机、灯光与纯色背景，渲染时隐藏其他网格和灯光；角色自身的隐藏状态和集合可见性仍需要预先检查。

批次完成、错误或取消后恢复原相机、灯光/其他网格的渲染可见性、骨骼姿势、形态键、世界背景及批次修改的渲染设置。手动应用的材质是持久编辑，不会在批次结束后撤销。渲染期间请等待完成，Esc 会在当前单张结束后停止，单张渲染期间界面可能无响应。

PNG 分辨率默认 1024 × 1024，范围 256–4096。36 张是起始素材，是否足以训练取决于角色复杂度与图片质量；应去掉穿模、重复、错误表情和错误标签。

## 开发验证

```powershell
python -m unittest discover -s tests -p test_*.py
& 'D:\Program Files\Blender 5.2\blender.exe' --background --factory-startup --python-exit-code 1 --python tests/blender_smoke.py
python tools/build_zip.py
```

上述普通检查不生成渲染图。对已保存的本机角色工程做三视图测试：

```powershell
python tools/run_three_views.py --games WUWA ZZZ --source "本机测试工程目录" --output "本机输出目录" --resolution 1024
```

`--source` 下应有 `WUWA/optimized.blend`、`ZZZ/optimized.blend` 等子路径；角色原贴图需仍然可访问。可通过 `--blender` 或 `BLENDER_EXECUTABLE` 指定 Blender 程序。首次从 PMX 测试可使用 `tools/run_real_model_tests.py --games WUWA --output 本机输出目录`，默认三视图；该脚本内的模型清单是本机示例，需要按资产位置修改。

集成测试会创建简化测试角色，验证材质切换、MMD 多贴图角色识别、半透明层保留、完整 36 张输出、标签清单、成功/取消/无效路径后的状态恢复。

另提供 `tools/run_real_model_tests.py`，对本机 `D:/mmd` 的六游戏模型进行独立 Blender 进程测试：龙晶、菲欧妮、納貝里士 T-Pose、锁暝、提弗洛斯、明音凛。可执行 `--phase audit` 检查贴图，`--phase preview` 渲染原材质对照及四类构图/表情/姿势，`--phase full` 运行每角色 36 张完整流程。使用 `--output` 指定输出目录，原 PMX 与贴图不作修改。真实模型不打包进插件 ZIP。

测试结果与模型使用权限分别记录。菲欧妮模型目录的 `RM.txt` 明确禁止 AI 训练/生成式 AI 数据集，本机渲染测试不构成训练许可。宽袖、披风等未进行物理稳定，测试产物仍需画面验收，界面 Esc 操作尚未做自动化测试。

参考：[Shader to RGB API](https://docs.blender.org/api/main/bpy.types.ShaderNodeShaderToRGB.html)、[渲染操作 API](https://docs.blender.org/api/main/bpy.ops.render.html)。
